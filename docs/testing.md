# Testing

How the platform is tested, what covers which requirement, and how to run everything. Decisions
behind the Phase 10 additions are in [ADR 0016](adr/0016-hardening.md).

## Layers

| Layer                             | Runner                        | Where                                                           | Needs                         |
| --------------------------------- | ----------------------------- | --------------------------------------------------------------- | ----------------------------- |
| Domain rules (pure functions)     | Vitest                        | `packages/domain/src/**/*.test.ts`                              | nothing                       |
| Contracts, i18n, client, UI kit   | Vitest                        | `packages/{validation,i18n,api-client,app-kit,ui}`              | nothing                       |
| Cloud API integration             | Vitest + real PostgreSQL      | `apps/api/test/*.test.ts`                                       | `TEST_DATABASE_URL` (`_test`) |
| Location hub integration          | Vitest + real SQLite          | `apps/gateway/test/*.test.ts` (with a fake cloud)               | nothing                       |
| Shared server units               | Vitest                        | `packages/server/src/**/*.test.ts`                              | nothing                       |
| Components (POS, KDS, web, admin) | Vitest + Testing Library      | `apps/*/src/**/*.test.tsx`                                      | nothing                       |
| End to end                        | Playwright (installed Chrome) | `apps/{admin,pos,kds,customer-web}/e2e/*.spec.ts`               | `*_e2e` databases, a build    |
| Repository tools                  | `node --test`                 | `tools/**/*.test.mjs` (lint rule, printer decoder, this matrix) | nothing                       |
| Tauri shell                       | `cargo test`, clippy, fmt     | `apps/pos/src-tauri`                                            | Rust                          |

## Running

```bash
pnpm typecheck && pnpm lint && pnpm test && pnpm build   # the gate (unit + integration)
pnpm e2e                                                 # every Playwright suite, one after another
pnpm test:tools                                          # tool tests, incl. the coverage matrix check
pnpm --filter @pos/pos rust:check                        # the desktop shell
```

`pnpm e2e` runs the four suites one at a time (`turbo run test:e2e --concurrency=1`; each starts
its own cloud, hub and web servers on its own ports and databases — see
[dev-setup.md](dev-setup.md#end-to-end-tests-playwright)). One suite:
`pnpm --filter @pos/pos test:e2e`; one file: `pnpm --filter @pos/pos exec playwright test e2e/sync.spec.ts`.

## Critical end-to-end scenarios

against the real built cloud API and/or location hub (no mocks): the POS and KDS suites run on a
hub whose cloud is **switched off** (it only runs to pair the hub, and in `sync.spec.ts` the test
starts and stops it); the customer-website suite runs cloud, hub, POS, KDS and website together.
`tools/e2e/coverage.test.mjs` fails if a test named here disappears or is renamed.

## Tenant isolation (MADAR, ADR 0017)

Many tenants share one cloud, so isolation is tested at three levels:

| What                                                                                                                                                  | Where                                                                                                           |
| ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Every route naming a tenant or location answers `404` to another tenant's owner                                                                       | `apps/api/test/security.test.ts` (walks the route inventory)                                                    |
| Tenant A cannot read, list, change, archive, transition, order or reuse ids of tenant B's rows through its own routes; forged `tenantId`s are ignored | `apps/api/test/tenant-isolation.test.ts`                                                                        |
| Reports' raw SQL over two tenants with identical orders                                                                                               | `apps/api/test/tenant-isolation.test.ts`                                                                        |
| The tenant-scoped client: filters, refused foreign writes, transactions, no scope refused (PostgreSQL); the same on SQLite                            | `apps/api/test/tenant-isolation.test.ts`, `apps/gateway/test/hub.test.ts`, `packages/server/src/common/tenancy` |
| Change feed after the rename, for every way a table names its tenant                                                                                  | `apps/api/test/tenant-isolation.test.ts`                                                                        |
| The hub refuses another tenant's snapshot and ambiguous PIN codes; a pre-rename hub upgrades with its data                                            | `apps/gateway/test/hub.test.ts`, `apps/gateway/test/migrator.test.ts`                                           |
| Unscoped (cross-tenant) access only in reviewed files                                                                                                 | lint rule `pos-local/no-unscoped-prisma` (`tools/eslint-rules`)                                                 |

Tenant files are covered when file storage arrives (Phase M3).
