# ADR 0003: UUIDv7 identifiers generated at the edge

- Status: Accepted (2026-10-17)

## Decision

Every entity id is a UUIDv7, generated by the node that creates the row: the hub offline, or
the cloud online. Postgres stores ids as `uuid`. UUIDv7 is time-ordered, so B-tree index
locality stays good.

The specification describes a temporary local id mapped to a cloud id after sync. With
collision-safe client-generated ids that mapping is unnecessary: **the local id is the cloud
id**. This removes a class of bugs (remapping foreign keys, duplicates after partial sync).

Human-readable order numbers are separate from ids. They are scoped per location and business
day and prefixed by their source (`<LOCATIONCODE>-042` from the hub, `W-017` from the web), so
two writers never collide.

Duplicate detection uses `operationId` and entity ids, never timestamps.
